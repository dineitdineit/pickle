# Pickle 개발 로드맵

작성·수정일: 2026-10-16
기준: [제품 방향서](./product-vision.ko.md)

## 확정한 현재 방향

**지금은 레시피와 요리 경험 공유에 집중한다.**

음식을 발견하고 저장한 뒤 직접 만들어 보고, 사진·후기·질문·답글로 경험을 나누는 흐름을 완성한다. 초기 핵심 대상은 필리핀의 요리 이용자와 작은 음식 크리에이터다.

장기적으로 글로벌 이용자에게 Cookpad형 요리 커뮤니티와 Tabelog형 신뢰할 만한 식당 정보를 연결하는 모습을 지향한다. 현재는 단일 앱을 유지하고, 맛집 기능은 후속 단계로 둔다. 두 영역의 본격적인 동시 개발이나 별도 앱 출시는 현재 범위에 포함하지 않는다.

## 1단계 — 현재 집중: 레시피와 요리 경험 공유

| 작업 영역 | 개발 방향 | 상태·확인 사항 |
| --- | --- | --- |
| 레시피 발견·열람·저장 | 사진으로 발견하고 재료·단계를 편하게 읽으며 저장한 음식을 다시 찾게 한다 | 기존 기반을 유지·개선 |
| 음식 사진과 짧은 글 | 직접 만든 음식·일상 요리·실패 경험을 가볍게 공유하게 한다 | 사진 게시·탐색·프로필의 첫 구현은 관련 문서에 기록됨. 공개 전 남은 운영·기기 검증 확인 필요 |
| 질문·답글 알림 | 실제 질문과 답변을 확인하고 해당 대화를 이어가게 한다 | 인앱 댓글·답글 알림과 해당 댓글 이동이 구현 문서에 기록됨. OS 푸시와 별개 |
| 원본과 만든 후기 연결 | ‘만들어 봤어요’ 사진·변경 사항·실패담을 원본 레시피 및 작성자와 연결한다 | 다음 핵심 개발 후보. 현재 사진 게시 기능과 연결 범위 확인 후 명세 작성 |
| 공개 참여의 신뢰 운영 | 사진 게시에도 신고·검토·조치, 차단과 AI 생성 표시 원칙을 적용한다 | 특히 사진 게시 전용 신고·관리 기능은 공개 전 보완 대상으로 문서에 명시됨 |
| 홈과 저장 재사용 | 사람들의 요리 경험과 저장한 음식으로 다시 접근하게 한다 | 초기 주간 주제는 작은 운영 실험으로 검증하고 자동화는 필요에 따라 진행 |
| 반복 이용 측정 | 다음 주·4주 후 활동, 첫 답변 시간, 이용자 간 반복 대화를 확인한다 | 기존 집계의 활용 범위와 추가 기록을 정하고 구현 |

위 구현 상태는 2026-10-16의 [댓글 알림 문서](./comment-notifications.md)와 [사진 게시 문서](./photo-posts.md)에 근거한다. 이 로드맵 작성 중 배포·운영 DB·실제 기기에서 독립적으로 재검증한 것은 아니다. ‘구현’과 ‘출시 완료’를 구분한다.

### 진행 순서

1. 기존 사진 게시·알림 작업의 남은 검증과 사진 게시 신고·관리 등 공개 준비를 확인한다.
2. 원본 레시피와 만든 사진 후기를 연결하는 참여 흐름을 구체화하고 개발한다. AI 표시 원칙도 게시 유형 전반에 맞춘다.
3. 크리에이터와 실제 요리 이용자를 소규모로 초대하고, 레시피 발견·저장·게시·질문·답변을 관찰한다.
4. 실제 불편을 바탕으로 홈·저장목록·작성 부담과 알림을 개선한다. 주간 주제는 운영 여력 안에서 하나씩 시험한다.
5. 반복 이용과 교류가 생기는지 확인한 뒤 새로운 영역의 개발 여부를 판단한다.

완료된 작업을 다시 만들지 않고 기존 기능을 연결한다. 세부 작업 순서와 출시일은 개별 검증 결과에 따라 조정한다.

## 2단계 — 필요가 확인되면: 요리 실행 지원

레시피를 실제로 만들어 먹는 과정에서 확인된 불편을 해결한다. 장보기 목록, 인분 조절, 재료 정리, 작성·번역 지원 등은 후보이며 모두 구현하기로 확정한 것은 아니다.

진입 조건: 같은 이용자 집단의 반복 사용이 관찰되고, 해당 기능이 필요한 구체적인 행동과 요청이 확인되어야 한다. 기능 수를 늘리기 위해 진입하지 않는다.

## 3단계 — 지역 수요가 확인되면: 신뢰할 만한 식당 정보

Tabelog를 참고하되 지역별 정보의 정확성·최신성과 방문 경험의 신뢰를 갖추는 방향으로 확장한다.

- 한 도시나 생활권의 식당 저장·장소 정보·방문 후기부터 범위를 정한다.
- 식당 정보와 레시피를 앱 안에서 명확히 구분하고 평점도 별도로 설계한다.
- 리뷰 조작, 이해관계·홍보 표시, 정보 수정·신고와 운영 절차를 함께 마련한다.
- 충분한 근거가 없는 식당 순위나 공정성을 보장하는 점수를 미리 약속하지 않는다.

진입 조건: 현재 커뮤니티에서 같은 지역의 식당 공유·저장·방문 후기가 반복되고, 정보를 관리할 역량이 있어야 한다. 사용자가 두 영역을 함께 쓰는지도 확인한다.

## 장기 선택지

글로벌 확장, 외부 구매·배달 연결, 자체 거래·배달은 실제 수요와 운영 역량을 확인한 뒤 별도 판단한다. 서비스가 세계를 대상으로 한다는 비전과 모든 지역을 동시에 운영한다는 계획은 구분한다.

두 앱 분리는 실제 이용자·이용 목적·유입 경로의 차이와 운영 조직이 뒷받침될 때 재검토한다. 현재 결정은 단일 앱에서 단계적으로 발전시키는 것이다.

## 현재 보류할 범위

- 종합 맛집 지도·식당 랭킹·예약 서비스의 본격 개발.
- 온라인 장보기 거래, 자체 결제·배달 사업.
- 데이터와 운영 필요가 확인되기 전의 고급 추천·다수의 빈 커뮤니티 공간.
- 일정 이용 규모 이전의 유료 게시물·구독제.

## 단계 전환 판단

회원·게시물 총수와 함께 처음 온 집단의 다음 주·4주 후 이용, 저장 재사용, 원본과 연결된 후기, 운영진을 제외한 이용자 간 대화를 확인한다. 운영자 독려·유료 지원과 자발적인 활동을 구분한다.

구체적인 수치·예산·일정은 아직 미정이다. 새로운 단계로 넘어갈 때 관찰 결과와 운영 가능성을 기록하고 결정한다.
