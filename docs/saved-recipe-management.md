# Saved recipe management

October 20, 2026. Saved is now independent of the home recipe catalogue.

- Search matches saved recipe titles and short descriptions, case-insensitively, on the server. It does not search unsaved recipes, create recent-search entries or record search analytics. `%` and `_` are literal query characters. Search is debounced by 250 ms and limited to 100 characters.
- Filter by All, Want to cook or Cooked. Existing and newly saved recipes default to Want to cook. A card's status picker changes the private account-owned `saved_recipes.cook_state`. No public recipe field, notification, review or cooking-mode progress is changed. Unsave removes that save and its cooking state; saving again starts at Want to cook. Account/recipe deletion cascades removal.
- The security-invoker `search_saved_recipes` RPC joins the account's saved rows directly to accessible recipes, ordered by save time and recipe ID. It returns 24 items plus one lookahead, with stable cursor pagination rather than a home-catalogue intersection or an offset cap. State/search filters run before pagination. Blocked, hidden, removed or otherwise inaccessible recipes remain excluded through existing RLS and visibility rules.
- Save identity/time cannot be changed by the client. End-user grants are select/delete, insert user/recipe IDs and update cooking state only. The previous inherited authenticated TRUNCATE privilege was revoked because RLS cannot protect that operation. Other-account cooking states remain inaccessible.
- State changes/removals require a matching server confirmation before changing the list. Failed writes retain the previous value and show an error. Per-card locks prevent double submissions. Load-more errors retain loaded cards and retry the same cursor. Late search/account responses are ignored, and a mutation finishing after a filter/focus reload triggers a fresh read. Focus and safety/block events refresh visible content. No device cache of the saved collection was added.

Tests include a rollback-only SQL fixture with 60 saved recipes and an unsaved recipe: default states, state changes, combined server search/filtering, a match beyond the first page, tied timestamps across pages, literal wildcard input, cross-account updates, immutable save IDs, invalid states/cursors, blocked/hidden content, unsave/resave and signed-out access. Unit/UI and hook tests cover independent RPC loading, lookahead cursors, mutation confirmation, stale responses, retry preservation and filter changes during mutations.

Verification: 278 automated tests passed; TypeScript, web build, Capacitor Android sync and JDK 21 debug APK build passed. On the Pixel 7 emulator, a temporary Chicken Adobo save defaulted to Want to cook, changed to Cooked, disappeared from Want to cook and appeared under Cooked. Searching for the unsaved Lumpiang recipe returned no match, while Adobo plus Cooked returned the saved card. The temporary save was removed and the original empty collection restored. SQL fixtures left no synthetic accounts or recipes. Screenshots: `screenshots/saved-recipes-native-2026-10-20.png` and `screenshots/saved-recipes-search-native-2026-10-20.png`. Security advisors reported no new warnings; the pre-existing admin-analytics and leaked-password-protection warnings remain separate.

Scope: cooking states are manual labels, not proof that a recipe was cooked. Recipe search covers name/short description; ingredient matching, collections/folders, shopping lists and automatic cooking-mode completion are outside this change.
