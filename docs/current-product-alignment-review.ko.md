# 현재 구현과 제품 방향의 적합성 검토

검토일: 2026-10-15
기준: [제품 방향서 1.1](./product-vision.ko.md), [재방문·교류 전략](./retention-community-strategy.ko.md)
범위: 현재 로컬 작업 디렉터리의 프런트엔드 코드와 관련 마이그레이션을 읽은 정적 검토. 실제 배포본·모바일 설치본·운영 DB의 적용 상태, 사용성·재방문 성과는 확인하지 않았다. 아래는 변경 제안이며 앱 코드를 수정한 기록이 아니다.

## 결론

**레시피 발견·열람·저장 서비스와 커뮤니티 기반 기능은 방향에 맞는다. 가벼운 공개 참여와 대화를 이어 주는 알림·홈·측정이 부족해, 현재 구조만으로 음식 커뮤니티의 반복 이용을 검증하기는 어렵다.**

전면 재개발보다는 기존 레시피·저장·팔로우·댓글·운영 기능을 연결하는 작업을 우선한다. 댓글 답글과 사진 DM은 이미 있으므로 새로 없는 기능처럼 취급하지 않는다. 음식 커뮤니티에 필요한 것은 가벼운 공개 음식 사진과 원본 레시피에 연결된 후기다.

## 현재 구현의 상태

| 영역 | 확인한 구현 | 방향과의 관계 |
| --- | --- | --- |
| 발견 | 사진 레시피, 검색·재료/종류 탐색, Featured·Trending·Under 30min·Party Packs | 음식 아이디어 발견에 맞지만 익숙한 사람과의 관계·주간 공동 경험이 홈에 연결되지 않음 |
| 레시피 열람 | 재료·단계·영양, 영상 링크, 시간·인분, 단위 전환 | 유지할 핵심 기반 |
| 저장 | 계정별 저장, 저장목록 재열람 | 개인적인 재방문 이유로 발전 가능 |
| 공개 게시 | 세 단계 레시피 작성과 검증 | 요리법 게시에 적합하나 사진과 짧은 글만으로 참여하는 길 부족 |
| 교류 | 댓글·답글·댓글 좋아요, 별점·텍스트 리뷰, 팔로우 | 기반이 이미 있음. 사진 후기와 대화 알림 연결 필요 |
| 알림 | 팔로우·새 레시피·운영 조치 | 자신에게 온 질문·답글을 확인할 유형과 대화 위치 연결 부족 |
| 메시지 | 개인 메시지와 사진 첨부 | 유지하되 공개 커뮤니티 경험의 대체로 보지 않음 |
| 신뢰 운영 | 신고·차단·숨김·제재·이의 제기, 동의 절차 등 | 유지할 기반. AI 표시와 관련 신고 경로 보완 필요 |
| 측정 | 조회·검색·저장·좋아요 집계와 활동 | 다음 주 재방문·반복 대화 평가로 확장 필요 |

## 우선 추가·보완할 것

### 우선 1: 댓글과 답글 알림

댓글·답글 자체는 `src/RecipeComments.tsx:5`, `:216`, `:623`에 구현되어 있다. 반면 `src/SocialScreen.tsx:24`의 알림 유형은 `follow`, `new_recipe`, `moderation`이며, `supabase/migrations/20261013063608_moderation_author_notifications.sql:7`의 제약도 동일하다.

원본 작성자에게 새 질문을, 댓글 작성자에게 답글을 전달하는 알림을 추가한다. 알림을 누르면 레시피 상단이 아닌 해당 댓글을 바로 찾게 한다. 자기 알림·중복·차단 관계와 알림 설정을 고려한다. 현재 알림 기반을 확장하는 작업이다.

### 우선 2: 사진과 짧은 글로 공개 참여

`src/RecipeUploadScreen.tsx:32`의 작성 경로는 Recipe details / Ingredients / Cooking steps다. `src/lib/submissions.ts:132`의 검증은 사진·제목·설명·인분·난이도·시간·재료·단계를 요구한다.

작성 시작점에 레시피와 음식 사진을 구분한다. 음식 사진에는 사진과 짧은 경험을 중심으로 요구하고 레시피의 재료·단계를 요구하지 않는다. 요리 성공·실패·오늘 먹은 음식 등을 공유할 수 있게 한다. 독립 게시물의 신고·차단·공개 범위도 함께 설계한다.

`src/MessagesScreen.tsx:498`의 사진 DM이 이 기능을 대신하지는 않는다. 기존 비공개 채팅 이미지를 공개 피드에 재사용하지 않는다.

### 우선 3: ‘만들어 봤어요’ 사진과 원본 연결

`src/lib/reviews.ts:4`의 Review와 `src/RecipeReviews.tsx:104`의 저장 경로는 별점·텍스트 중심이며, 공개 음식 사진 후기나 원본과 연결된 새 게시물 경로가 확인되지 않는다.

레시피에서 사진과 변경 사항·실패담을 공유하고, 원본 레시피와 작성자를 연결한다. 새 레시피 전체를 다시 작성하거나 반드시 별점을 매기지 않아도 경험을 공유할 수 있게 한다. 기존 별점 리뷰는 유지한다. 원작자가 반응할 알림까지 연결한다.

### 우선 4: AI 표시와 구체적인 신고 이유

검토한 레시피 입력·출력·카드와 마이그레이션에서 AI 생성 여부를 저장하고 표시하는 전용 흐름을 찾지 못했다. 업로드 시 선언, 저장 필드, 목록·상세 표시를 연결한다. 일부 AI 사용의 기준은 정책으로 정한다.

`src/ReportButton.tsx:6`은 일반적인 신고 사유를 제공한다. 위험한 레시피·리뷰 조작·AI 생성 미표시를 명확히 신고하고 기존 운영 대기열에서 검토할 수 있도록 보완한다. 자동 탐지 하나로 제재하지 않는다.

### 우선 5: 관계와 공동 경험이 보이는 홈

`src/App.tsx:357`의 홈 조회는 전체 레시피 중심이다. 홈 카드용 조회에는 작성자 정보가 없고, `src/DesktopHome.tsx:163` 이후의 콘텐츠는 Trending·빠른 요리·Party다.

현재 홈을 유지하면서 ‘이번 주 같이 만드는 음식’, 팔로우한 사람의 새 게시물, 새 사진 후기를 연결한다. 이용량이 적으면 여러 빈 피드로 나누지 않고 한 홈에서 모아 보여준다. 주간 주제는 처음부터 자동화하지 않아도 운영자가 편집해 검증할 수 있다.

### 우선 6: 저장목록의 재사용

`src/SavedScreen.tsx:70`은 저장한 레시피를 저장일 순으로 가져온다. 저장 기능을 다시 만들기보다 ‘이번 주 해볼 것’, ‘만들어 본 것’ 같은 단순 상태와 홈의 재접근 경로를 검토한다. 복잡한 폴더 관리보다 실제 재열람과 요리 연결을 먼저 확인한다.

### 우선 7: 재방문·교류 측정

`src/AdminAnalytics.tsx:1`과 `:21`의 중심 지표는 조회·검색·저장·좋아요다. 집계는 유지하고 처음 방문한 집단별 다음 주·4주 후 활동, 첫 답변 시간, 운영진을 제외한 상호 답글, 사진 후기와 저장 재사용을 추가한다.

DB 기록 일부로 계산할 수 있는 항목과 새 활동 기록이 필요한 항목을 먼저 나눈다. 기존 데이터가 전혀 없다고 전제하거나 개인정보를 불필요하게 더 수집하지 않는다. 현재 운영 데이터를 조사한 것은 아니므로 기존 지표의 정확성과 실제 계산 가능 범위는 별도 확인한다.

### 다음 단계: 크리에이터의 외부 계정과 공유

`src/UserProfileScreen.tsx:14`의 프로필 정보는 이름·사진·소개 등이며, 외부 SNS 계정을 등록·링크하는 전용 경로를 확인하지 못했다. `src/lib/share.ts:5`에는 레시피 공유 링크가 이미 있으므로 유지한다.

안전하게 외부 계정을 표시하고 프로필 자체를 공유할 경로를 추가하면, 초대 시 약속한 크리에이터 가치를 구체화할 수 있다. URL을 통한 작성자 접근은 현재 레시피 공유와 별도로 검토한다.

위 항목은 삭제해야 할 코드 목록이 아니다. 노출 우선순위 조정, 기존 기능 수정, 신규 확장 보류를 구분해 적용한다. 조회 지표 수집, 별점, 검색·저장, 메시지, 운영 기능을 일괄 삭제하지 않는다.

## 유지할 것

- 사진을 통한 레시피 발견, 검색과 재료·요리 종류 탐색.
- 재료·조리 단계·선택적 영양 정보, 단위 전환, 시간·인분, 영상 링크. 영양 정보는 이미 선택 입력이므로 필수 입력인 것처럼 제거할 필요가 없다.
- 저장·좋아요·텍스트 리뷰, 이미 있는 댓글·답글·팔로우·새 레시피 알림.
- 외부에서 특정 레시피로 들어오는 공유 링크와 로그인 전 콘텐츠 탐색 경로.
- 차단·신고·숨김·제재·이의 제기·계정 삭제·동의와 관련 운영 도구. 초기 범위를 줄인다는 이유로 없앨 대상이 아니다.

## 추천 실행 순서

1. 기존 댓글·답글 알림과 해당 대화로 이동하는 경로를 연결하고 첫 반응·재방문 측정을 준비한다.
2. AI 생성 표시와 필요한 신고 사유를 보완한다. 공개 게시물 유형을 늘릴 때 같은 기준을 적용한다.
3. 음식 사진 게시와 원본에 연결된 만든 사진 후기를 하나의 참여 설계로 함께 구현한다.
4. 홈의 Featured·Party 노출 일부를 주간 주제와 사람들의 실제 경험으로 교체하고 저장 재사용을 돕는다.
5. 작은 모집 집단에서 반응을 확인한 뒤 외부 프로필 연결·추천·관심사 공간을 확장한다.

현재 코드에서 잘 갖춰진 부분은 활용하고, ‘레시피를 본 뒤 돌아올 사건과 참여할 방법’을 연결하는 데 다음 개발을 집중한다.
